# Лабораторная работа: Разработка микросервиса (RESTful API, Docker, PostgreSQL)

## Описание проекта
Микросервис управления задачами (Task Management API), реализованный на базе **Python 3.11**, **FastAPI** и реляционной СУБД **PostgreSQL 15**. Проект упакован в контейнеры при помощи **Docker Compose** с использованием **Multi-stage build** в `Dockerfile`.

## Реализованные требования
1. **RESTful API**: реализовано 5 эндпоинтов:
   - `POST /api/v1/tasks/` — создание задачи (201 Created);
   - `GET /api/v1/tasks/` — получение списка всех задач с пагинацией и фильтрами (200 OK);
   - `GET /api/v1/tasks/{id}` — получение конкретной задачи по ID (200 OK / 404 Not Found);
   - `PUT /api/v1/tasks/{id}` — обновление полей задачи (200 OK / 404 Not Found);
   - `DELETE /api/v1/tasks/{id}` — удаление задачи (200 OK / 404 Not Found).
2. **СУБД**: реляционная база данных PostgreSQL 15, связь через SQLAlchemy ORM.
3. **Multi-stage Dockerfile**:
   - Этап 1 (`builder`): сборка и компиляция зависимостей в виртуальное окружение `/opt/venv`;
   - Этап 2 (`runner`): перенос только готового виртуального окружения в легковесный чистый образ, запуск под непривилегированным пользователем `appuser` (security best practice).
4. **docker-compose.yml**:
   - Автоматический подъем двух связанных сервисов: `db` (PostgreSQL) и `app` (FastAPI);
   - Ожидание готовности БД с помощью `healthcheck` и `condition: service_healthy`;
   - Изоляция во внутренней сети `microservice_net` и сохранение данных в именованном томе `postgres_data`.
5. **Обработка ошибок и логирование**:
   - При некорректных данных (например, пустой заголовок задачи `title: ""`) сервис не падает, а возвращает HTTP-код `422 Unprocessable Entity` с подробным описанием ошибки;
   - При запросе несуществующего ресурса возвращается HTTP-код `404 Not Found`;
   - Внедрен Middleware логирования: каждый запрос, IP клиента, HTTP-метод, время обработки в миллисекундах и ошибки логируются в stdout/stderr.
6. **Документирование API (Swagger)**:
   - Автоматически доступна интерактивная документация Swagger UI по адресу `http://localhost:8000/docs`.
7. **Проверка через Postman**:
   - В корне проекта подготовлена коллекция `postman_collection.json` с предустановленными переменными окружения и сценариями тестов (включая проверку ошибок 404 и 422).

## Запуск проекта

### Шаг 1. Запуск Docker Desktop
Убедитесь, что Docker Desktop запущен на вашем компьютере.

### Шаг 2. Запуск контейнеров
В терминале перейдите в папку проекта и выполните команду:
```bash
docker compose up --build -d
```

### Шаг 3. Проверка статуса
```bash
docker compose ps
docker compose logs app
```

Микросервис будет доступен по адресу:
- Главная страница (Healthcheck): [http://localhost:8000/](http://localhost:8000/)
- Swagger UI (документация): [http://localhost:8000/docs](http://localhost:8000/docs)

---

## Проверка через Postman
1. Откройте Postman.
2. Нажмите **Import** и выберите файл `postman_collection.json`.
3. Запустите запросы по очереди:
   - `0. Healthcheck` (GET `http://localhost:8000/`)
   - `1. POST - Создать задачу 1` (Создает задачу и сохраняет ее ID в переменную `taskId`)
   - `2. POST - Создать задачу 2`
   - `3. GET - Получить все задачи`
   - `4. GET - Получить задачу по ID`
   - `5. PUT - Обновить задачу`
   - `6. DELETE - Удалить задачу`
   - `7. Ошибка 404 - Запрос несуществующей задачи`
   - `8. Ошибка 422 - Валидация (пустой заголовок)`

---

## Остановка сервиса
```bash
docker compose down
```
Для остановки с полным удалением данных из тома PostgreSQL:
```bash
docker compose down -v
```
